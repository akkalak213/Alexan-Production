# Design Critique — Alexan Production

วันที่ตรวจ: 10 กันยายน 2026

ขอบเขต: เว็บไซต์ธุรกิจสำหรับลูกค้าที่ต้องการเว็บไซต์ แอป งานภาพ วิดีโอ และสตูดิโอ เป้าหมายหลักคือเข้าใจบริการ ดูผลงาน แล้วส่งคำขอให้ทีมติดต่อกลับ ช่วงงาน: refinement ก่อนเปิดตัวเวอร์ชันใหม่

หลักฐาน: หน้าแรกที่ http://localhost:3000/ จาก working tree ใน D:\Alexan Production (ฐาน commit 1bd7bd1 พร้อมการเปลี่ยนแปลงที่ยังไม่ commit) ตรวจหน้าไทยขนาด 1440×1000 และ 390×844, ธีมสว่าง/มืดบนมือถือ, เมนูด้วยคีย์บอร์ด และคลิกไปหน้าติดต่อ อ่านโค้ดประกอบเรื่อง form, tokens และข้อมูลตัวอย่าง

ข้อจำกัด: ไม่ได้ตรวจเว็บ production ในรอบนี้ ไม่ได้ส่งฟอร์มจริง ไม่ได้ทดสอบ screen reader, iOS จริง, 200% text enlargement หรือทุกหน้าภาษาอังกฤษ หน้าติดต่อแสดง 404 จึงประเมินรายละเอียดฟอร์มจากโค้ดเท่านั้น มีการแก้ working tree ระหว่างตรวจ ให้ใช้ผลนี้เป็น snapshot และตรวจซ้ำก่อน deploy

## ภาพรวม

โทนทองแดง พื้นหลังสว่าง และ serif ของชื่อแบรนด์ช่วยให้เว็บมีบุคลิกสตูดิโอชัดเจน ปุ่มหลักแยกจากปุ่มดูผลงานดี แต่หัวเรื่องที่ใหญ่และข้อความทั่วไปใช้พื้นที่มากกว่าหลักฐานผลงานจริง จุดที่ต้องแก้ก่อนตกแต่งต่อคือเส้นทางปุ่มติดต่อที่เปิด 404

## Visual hierarchy

สิ่งที่ดึงสายตาก่อนคือ headline และปุ่มทองแดง ถูกทิศทางสำหรับการขายบริการ แต่คำว่า “เราสร้างสิ่งที่ธุรกิจคุณต้องใช้จริง” ยังไม่บอกความเชี่ยวชาญเมื่อเห็นเดี่ยว ๆ ข้อความรองจึงต้องทำงานหนัก

ที่ 1440px H1 มีขนาด 104px, line-height 156px และสูง 468px เป็นสามบรรทัดในคอลัมน์กว้างประมาณ 672px ส่วนมือถือเห็นปุ่มหลักได้ในจอแรก แต่ยังไม่เห็นผลงาน ต้องลดพื้นที่หัวเรื่องโดยรักษาสระไทย ไม่บังคับตัดบรรทัดด้วย br ชุดเดียวทั้งสองภาษา

ลำดับปัจจุบัน: ข้อความ → CTA → chips บริการ 6 รายการ → สถิติ → ภาพผลงานบนมือถือ → บริการ → สตูดิโอ → ผลงาน → รีวิว → CTA ซ้ำ

ลำดับเสนอ: ข้อความเฉพาะงาน → CTA → ผลงานเด่นจริง → ทางเข้าบริการ/สถิติที่ยืนยัน → บริการ → ผลงาน → สตูดิโอ → รีวิว → CTA ตอนท้าย ใช้เนื้อหาและความสามารถเดิม

## Accessibility: ผลคำนวณคู่สี

คำนวณจากค่า HSL ใน :root และ .dark ของ src/app/globals.css ด้วย relative luminance ของ sRGB ตัวเลขนี้เป็นคู่สี solid ไม่รวม gradient, opacity, hover หรือภาพด้านหลัง และไม่ใช่ผล audit WCAG ทั้งเว็บ

| คู่สี | Light | Dark | การอ่าน |
| --- | --- | --- | --- |
| foreground / background | 17.73:1 | 17.77:1 | ผ่าน 4.5:1 |
| muted-foreground / background | 5.43:1 | 8.04:1 | ผ่าน 4.5:1 |
| accent / background | 4.03:1 | 9.66:1 | Light ไม่ผ่านข้อความปกติ |
| accent-foreground / accent | 4.20:1 | 9.53:1 | Light ไม่ผ่านข้อความปกติ |
| accent / subtle | 3.79:1 | 8.76:1 | Light ไม่ผ่านข้อความปกติ |
| input border / surface | 1.35:1 | 1.41:1 | ต้องตรวจขอบเขต control ในบริบทจริงเพิ่มเติม |

เกณฑ์ข้อความปกติ 4.5:1 อ้างอิง [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum) ข้อความใหญ่มีเกณฑ์ต่างกัน ไม่ควรตัดสินจากสีอย่างเดียว

เป้าสัมผัส 44×44px เป็นเป้าดีไซน์ของโปรเจกต์ ไม่ใช่การกล่าวว่า AA บังคับ 44px; WCAG 2.2 AA กำหนด 24×24 CSS px โดยมีข้อยกเว้น ดู [WCAG 2.2](https://www.w3.org/TR/WCAG22/#target-size-minimum)

การกักและคืนโฟกัสของ modal อ้างอิง [W3C Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## สิ่งที่ควรรักษา

- แบรนด์และโทนสีมีบุคลิก; ภาษาไทย/อังกฤษมี font stack แยกชัดเจน
- CTA สองระดับชัดเจน ขนาด 48px บนมือถือกดได้สะดวก
- ที่ 390px ไม่พบการล้นแนวนอนของหน้าแรกใน snapshot ที่ตรวจ
- มี skip link, focus-visible และ reduced-motion rules อยู่แล้ว
- การ์ดเป็นลิงก์ทั้งใบและภาพมี aspect ratio สำรองพื้นที่
- โหมดมืดมี contrast คู่สีหลักที่ดี
