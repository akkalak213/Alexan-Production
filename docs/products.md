# ผลิตภัณฑ์ (โปรแกรม ระบบ เทมเพลต สินค้า)

หน้า `/products` กับ `/products/[slug]` แสดงของที่ Alexan Production พัฒนาเองและขาย
จัดการที่หลังบ้าน **เนื้อหาเว็บไซต์ → ผลิตภัณฑ์** (`/admin/products`)

## ประเภท

| ประเภท | ใช้กับ | ข้อมูลที่ส่งให้ Google |
|---|---|---|
| โปรแกรม (ซื้อขาด) | โปรแกรมติดตั้งในเครื่อง ขายเป็น license | `SoftwareApplication` |
| ระบบรายเดือน/รายปี | เว็บแอปหรือระบบออนไลน์ คิดค่าบริการเป็นรอบ | `SoftwareApplication` |
| เทมเพลต/ไฟล์ดิจิทัล | เทมเพลตเว็บ พรีเซ็ต ไฟล์ดาวน์โหลด | `Product` |
| สินค้า (จัดส่ง) | ของที่ต้องส่งถึงมือลูกค้า | `Product` |

## แพ็กเกจราคา

แต่ละผลิตภัณฑ์มีได้หลายแพ็กเกจ แต่ละแพ็กเกจมีราคา รอบการคิดเงิน (ซื้อขาด / ต่อเดือน / ต่อปี / สอบถามราคา)
สิ่งที่ได้รับ (บรรทัดละข้อ) และลิงก์ซื้อของตัวเองถ้ามี

- "เริ่มต้น" บนการ์ดและหัวหน้ารายละเอียดคือแพ็กเกจที่ **ถูกที่สุด** — ค่าต่ออายุหรือของเสริมจึงควรเขียนไว้ในสิ่งที่ได้รับ ไม่ใช่แยกเป็นแพ็กเกจ
- ราคาแปลงเป็นข้อความที่ `src/lib/product-pricing.ts` ที่เดียว หน้าเว็บ คำขอของลูกค้า และใบเสนอราคาจึงเขียนตรงกันเสมอ
- แพ็กเกจแก้ทีละแถวตาม id ไม่ลบทิ้งทั้งชุด (`src/lib/product-plans.ts`) ลิงก์ `?plan=` ที่ลูกค้าแชร์ต่อกันจึงไม่ตาย

## ลูกค้าซื้ออย่างไร

| ช่องทาง | ตั้งค่า | ลูกค้าเห็น |
|---|---|---|
| ส่งคำขอ / ขอเดโม | เป็นค่าเริ่มต้นเสมอ | ปุ่ม "สนใจซื้อ / ขอเดโม" และ "เลือกแพ็กเกจนี้" พาไปฟอร์มท้ายหน้า ติดแพ็กเกจที่เลือกไปด้วย |
| ร้านค้าภายนอก | ลิงก์ร้านค้าของผลิตภัณฑ์ หรือลิงก์ซื้อของแพ็กเกจ | ปุ่ม "ซื้อเลย" เปิดแท็บใหม่ พร้อมปุ่ม "สอบถามก่อนซื้อ" |
| ทดลองใช้ | ลิงก์ทดลองใช้ | ปุ่ม "ทดลองใช้" บนหัวหน้า |

คำขอจากหน้าผลิตภัณฑ์เข้ากล่องคำขอลูกค้าเหมือนคำขออื่น ที่มา "หน้าผลิตภัณฑ์"
ชื่อผลิตภัณฑ์ แพ็กเกจ และราคา ณ ตอนที่ลูกค้ากดถูกเก็บเป็นข้อความ (ช่องเดียวกับแพ็กเกจบริการ)
แก้ราคาหรือลบผลิตภัณฑ์ภายหลังก็ยังเห็นว่าลูกค้าขออะไรที่ราคาเท่าไหร่ ฝั่ง server อ่านชื่อกับราคาจากฐานข้อมูลเอง ไม่เชื่อข้อความจากฟอร์ม

กด "ออกใบเสนอราคา" จากคำขอ รายการแรกตั้งเป็นผลิตภัณฑ์กับแพ็กเกจที่เลือกพร้อมราคา
สินค้าจับต้องได้ตั้งหัก ณ ที่จ่ายไว้ 0% ผลิตภัณฑ์อื่นใช้อัตราของงานบริการ — มีข้อความเตือนให้ตรวจกับฝ่ายบัญชีเหนือฟอร์ม

### ชำระเงินออนไลน์บนเว็บ — ยังไม่ได้ทำ

ต้องมีบัญชี payment gateway ก่อน (เช่น Omise หรือ Stripe ที่รับ PromptPay และบัตร) แล้วต้องตัดสินใจเรื่อง
การออกใบกำกับภาษี การคืนเงิน การส่งมอบไฟล์หรือ license และที่อยู่จัดส่งของสินค้า
โครงข้อมูลตอนนี้รองรับการต่อเพิ่ม: แพ็กเกจมีราคาและรอบการคิดเงินชัดเจน ต่อระบบตะกร้ากับคำสั่งซื้อเข้าไปได้โดยไม่ต้องแก้ข้อมูลเดิม

## สถานะ

- **ฉบับร่าง** ไม่ขึ้นหน้าเว็บ ใช้เตรียมข้อมูล
- **เผยแพร่แล้ว** ขึ้นหน้า `/products`, sitemap และ `llms.txt`
- **เก็บเข้าคลัง** ไม่ขึ้นหน้าเว็บ แต่คำขอเก่ายังอ้างถึงได้
- ติ๊ก "เปิดรับคำสั่งซื้อ" ออก = หน้ายังอยู่ แต่ขึ้นป้าย "ปิดรับชั่วคราว" และซ่อนปุ่มซื้อผ่านร้านค้า ลูกค้ายังส่งคำขอทิ้งไว้ได้
