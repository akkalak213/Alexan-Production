# ความเร็ว ความเสถียร และความถูกต้องของข้อมูล

สรุปสิ่งที่ระบบทำเพื่อให้หน้าเว็บเร็ว หลังบ้านบันทึกไม่พัง และตัวเลขบนเอกสารไม่ผิด
พร้อมสิ่งที่ยังทำเพิ่มได้จาก dashboard ของ Cloudflare และ Railway

## วัดจากของจริงก่อนแก้ (13 ก.ย. 2026)

| จุด | ผล | ความหมาย |
|---|---|---|
| เซิร์ฟเวอร์ | Railway `asia-southeast1` (สิงคโปร์) 1 replica | ใกล้ไทยอยู่แล้ว ไม่ต้องย้าย |
| เวลาเรนเดอร์หน้าแรกที่เซิร์ฟเวอร์ | p50 ราว 50–60ms | เร็วอยู่แล้ว เวลาที่เหลือของ TTFB (~250ms) เป็นระยะทางเครือข่าย |
| ตัวย่อรูป `/_next/image` | p50 สูงสุด 871ms, p95 ถึง 7 วินาที (หมดเวลา) | คอขวดจริงของความรู้สึกช้า |
| RSC payload หน้าแรก | 134KB จาก HTML 274KB | ครึ่งหนึ่งคือไฟล์แปลทั้งไฟล์ที่ส่งไปทุกหน้า |
| Cloudflare | `cf-cache-status: DYNAMIC` ทั้ง HTML และรูปที่ย่อแล้ว | ไม่มีอะไรถูกแคชที่ขอบเครือข่ายเลย |

## แคชข้อมูลหน้าเว็บ

หน้าเว็บทุกหน้าต้องเรนเดอร์ใหม่ทุกคำขอ เพราะ CSP สุ่ม nonce ใหม่ทุกครั้ง แต่ข้อมูลในหน้าไม่ต้องอ่านใหม่ทุกครั้ง

- ทุก query ใน `src/server/queries.ts` และค่าตั้งค่าใน `src/lib/settings.ts` ห่อด้วย `cachedQuery` (`src/server/cache.ts`)
- ผลเก็บข้ามคำขอ ติดแท็กตามตารางที่แสดง: `services` `projects` `equipment` `reviews` `posts` `team` `settings`
- action หลังบ้านเรียก `updateTag` ทันทีหลังบันทึก คนแก้เปิดหน้าเว็บดูก็เห็นของใหม่เลย ไม่เห็นของเก่าอีกหนึ่งรอบ
- หมดอายุสำรองหนึ่งชั่วโมง เผื่อมีการแก้ฐานข้อมูลตรง ๆ โดยไม่ผ่านหลังบ้าน
- error ไม่ถูกเก็บลงแคช ฐานข้อมูลสะดุดครั้งเดียวไม่ค้างเป็นหน้าเสียทั้งชั่วโมง
- `src/lib/cache-serialization.ts` คืน `Date` และ `Decimal` เป็นชนิดเดิมหลังผ่าน JSON

**เพิ่ม query ใหม่:** ห่อด้วย `cache(cachedQuery('ชื่อ', [แท็ก], fn))` และติดแท็ก **ทุกตาราง** ที่ผลลัพธ์แสดง
ไม่ใช่แค่ตารางหลัก เช่นหน้ารายละเอียดผลงานแสดงชื่อบริการด้วย จึงติดทั้ง `projects` และ `services`
**เพิ่ม action ใหม่ที่แก้ข้อมูลหน้าเว็บ:** เรียก `updateTag` ของแท็กนั้นด้วย ไม่งั้นหน้าเว็บจะเห็นของเก่าจนครบชั่วโมง

## ภาพ

- ภาพที่ย่อแล้วเก็บไว้ 31 วัน (เดิม 4 ชั่วโมง) และลดจำนวนขนาดที่ย่อได้ แคชจึงถูกใช้ซ้ำบ่อยขึ้น
- หลังบ้านย่อภาพฝั่งเบราว์เซอร์ก่อนอัปโหลด: ด้านยาวไม่เกิน 2560px เป็น WebP (`src/lib/upload-client.ts`)
  ภาพจากกล้องที่เคยหนักหลาย MB เหลือไม่กี่ร้อย KB ตัวย่อรูปทำงานเร็วขึ้นหลายเท่า
- **ภาพที่อัปโหลดไปก่อนหน้านี้ยังเป็นไฟล์ใหญ่** ครั้งแรกที่มีคนเปิดยังช้า หลังจากนั้นใช้แคช 31 วัน
  ถ้าต้องการให้เร็วตั้งแต่ครั้งแรก ต้องแปลงไฟล์เดิมบน R2 ใหม่ทั้งหมด (เขียนทับข้อมูลจริง ต้องตัดสินใจก่อนทำ)

### ทำเพิ่มได้จาก dashboard (ได้ผลมากที่สุด)

1. **Cloudflare Cache Rule สำหรับรูป** — Caching → Cache Rules → สร้างกฎ
   เงื่อนไข URI Path starts with `/_next/image` → Eligible for cache, Edge TTL ใช้ค่าจาก origin
   รูปที่ย่อแล้วจะถูกเก็บที่ Cloudflare กรุงเทพฯ ผู้เข้าชมคนถัดไปได้รูปในไม่กี่สิบมิลลิวินาทีโดยไม่ต้องวิ่งถึงสิงคโปร์
   (Next ส่ง `Cache-Control: public, max-age=2678400` อยู่แล้ว)
   **ห้ามตั้งกฎนี้กับหน้า HTML** เพราะแต่ละหน้ามี nonce ของตัวเอง
2. **Railway volume สำหรับแคชรูป** — mount ที่ `/app/.next/cache` แคชรูปที่ย่อแล้วจะไม่หายทุกครั้งที่ deploy
3. **โดเมนของตัวเองสำหรับ R2** แทน `pub-….r2.dev` ซึ่ง Cloudflare จำกัดความเร็วและไม่แนะนำให้ใช้กับเว็บจริง
   ต้องเปลี่ยน `R2_PUBLIC_URL` และแก้ URL ที่บันทึกไว้ในฐานข้อมูลตามไปด้วย

## เงินและเอกสาร

- คิดเงินเป็นสตางค์ด้วย BigInt ปัดครึ่งขึ้นที่สตางค์ทีละขั้น (`src/lib/money.ts`)
  ใช้ร่วมกันใน `quote-math.ts` (ใบเสนอราคา), `rental-pricing.ts` (ค่าเช่า), `baht-text.ts` (ตัวอักษร)
- ตัวอย่างที่สูตรเดิมผิด: VAT 7% ของ 107.50 ได้ 7.52 (ถูกคือ 7.53),
  100.01 อ่าน "หนึ่งร้อยบาทเอ็ดสตางค์" (ถูกคือ "หนึ่งสตางค์"), 10,000,001 อ่าน "สิบล้านหนึ่ง" (ถูกคือ "สิบล้านเอ็ด")
- ฟอร์มฝั่งเบราว์เซอร์กับ server ส่งข้อความตามที่พิมพ์เข้าสูตรเดียวกัน ยอดบนจอจึงตรงกับยอดที่บันทึก
- server ปฏิเสธจำนวนติดลบ จำนวนเป็นศูนย์ ข้อความที่ไม่ใช่ตัวเลข ส่วนลดเกินยอด อัตราภาษีนอก 0–100%
  และตัวเลขที่เกินขนาดคอลัมน์ พร้อมข้อความบอกว่ารายการไหนผิด
- จำนวน ราคา และอัตราที่บันทึก คือค่าชุดเดียวกับที่ใช้คำนวณ ไม่ปล่อยให้ฐานข้อมูลปัดทศนิยมเองทีหลัง

| ส่วน | ทำอะไร |
|---|---|
| ใบเสนอราคา | แก้ตัวเอกสารกับแทนที่รายการในทรานแซกชันเดียว เทียบเวอร์ชันกับเขียนในคำสั่งเดียว (กันเขียนทับ) |
| เลขเอกสาร QT/AX | ต่อจากลำดับสูงสุดของเดือน ถ้าชนกันลองเลขถัดไป (เดิมนับจำนวน ลบเอกสารแล้วเลขชน) |
| สถานะคำขอ | ออกหรือส่งใบเสนอราคาเลื่อนเป็น "เสนอราคาแล้ว" เฉพาะคำขอที่ยังไม่ปิดการขาย |
| ผลงาน | ตัวผลงานกับแกลเลอรีบันทึกในทรานแซกชันเดียว |
| ค่าตั้งค่า | สี่กลุ่มบันทึกพร้อมกันหรือไม่บันทึกเลย |
| ฟอร์มสาธารณะ | บันทึกลงฐานข้อมูลก่อนตอบกลับ ส่งอีเมลแจ้งทีมหลังตอบกลับ ผู้กรอกไม่ต้องรอ Resend |

## เวลา

เซิร์ฟเวอร์ใช้ UTC ช้ากว่าไทยเจ็ดชั่วโมง ทุกจุดที่มีผลกับเอกสารจึงระบุ `Asia/Bangkok`:
รหัสเดือนในเลขเอกสาร วันที่บนใบเสนอราคา อีเมล หน้าพิมพ์ ใบเสนอราคาเบื้องต้น และต้นเดือนบนแดชบอร์ด
(`src/lib/bangkok-time.ts`)
